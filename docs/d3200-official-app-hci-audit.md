# D3200 (03.56): безопасное сравнение Bluetooth-команд с Soundcore App

## Что известно из аппаратного теста Pocket HUD 1.0.66

В логе от 22 ноября 2026 года, сессия 14:15:55–14:16:37, подтверждено:

- BLE GATT и ECDH 2E/01 проходят, информация устройства 01/01 доступна.
- Firmware 03.56, advertisement bound_bit_set: устройство сообщает, что **оно уже привязано**, но это **не доказывает авторизацию Pocket HUD**.
- Start recording 18/82 возвращает FF, однако запись физической кнопкой вызывает 1A/06.
- Realtime 1A/07 с флагом 1 возвращает FF.
- После остановки и паузы три секунды оба списка 1B/0E и 1A/0E возвращают FF.
- Completed 1A/07 с флагом 0 возвращает FF **дважды**, с интервалом пять секунд. Второй запрос фактически выполнен в 14:16:26.
- GATT после второго отказа закрыт штатно. Отдельный stop сервиса произошёл спустя 11 секунд, поэтому он **не вызвал** отказ FF.
- OpusReceived=0, PCMDecoded=0. Архитектура Gemini Live не является причиной отказа устройства на BLE уровне.

Следующий информативный тест — **пассивно записать BLE-обмен официального Soundcore App 5.0.39 с уже привязанным D3200** на той же firmware 03.56. Нельзя предполагать, что прошивки 04.73/04.82 из сторонних проектов ведут себя одинаково.

## Как собрать безопасный анализ без root

1. НЕ выполнять OTA, factory reset, unbind/rebind, очистку данных Soundcore App, удаление записей и изменение учётной записи. Если приложение предложит обновить firmware, отказаться. Сначала сохранить важные записи.
2. На Motorola Edge 50 Pro: Android Настройки → Для разработчиков → **Bluetooth HCI snoop log** → Enable / Full (если есть выбор).
3. Полностью закрыть Pocket HUD. Открыть штатное Soundcore App, подключиться обычным способом к текущей привязке. Можно попробовать короткую запись с кнопки устройства и посмотреть, показывает ли приложение запись; команды, изменяющие привязку, не использовать. Имей в виду, что штатное приложение может автоматически синхронизировать записи.
4. Сформировать bugreport в параметрах разработчика («Создать отчёт об ошибке») или через Android Platform Tools: **adb bugreport bugreport.zip**.
5. **Не отправлять сырые ZIP bugreport или btsnoop в чат или GitHub.** Они могут включать MAC-адреса, личные логи, другие Bluetooth-устройства, ключевой материал и аудио.
6. Локально запустить Python 3.9+ из репозитория Pocket HUD:

       python tools/d3200_hci_audit.py bugreport.zip -o official_redacted.json
       python -m unittest discover -s tools -p test_d3200_hci_audit.py -v

   На Android возможно использовать Termux с Python и разрешённым доступом к сохранённому bugreport, если в ZIP действительно присутствует btsnoop_hci.log.
7. Открыть official_redacted.json. Проверить, что в нём только относительные времена, тип/ID команды, направление, статус, длина и разрешённые значения флагов. **Отправлять только этот обезличенный JSON**.
8. Выключить Bluetooth HCI snoop log после сбора.

Если инструмент выводит «No D3200 frames found», это не означает, что официальный клиент не общался с устройством. Некоторые bugreport содержат только сжатый btsnooz или отфильтрованный лог. Инструмент поддерживает **полный H4 BTSnoop**, не произвольный txt/btsnooz. На Android с неполным логированием результат может быть недостаточен.

Документация Android:
- https://source.android.com/docs/core/connect/bluetooth/verifying_debugging
- https://developer.android.com/studio/debug/bug-report

## Что делает анализатор

- Читает btsnoop H4 (datalink 1002), HCI ACL и фрагменты L2CAP ATT, GATT Write / Notification.
- Извлекает только валидные кадры D3200 (префиксы 08 EE и 09 FF, контрольная сумма), включая ещё не известные типы команд инициализации, но скрывает их содержимое.
- Выводит относительное время, направление, тип/ID команды, длину payload, status и FF при коротком отказе.
- Допускает только неопасные для приватности поля: флаг realtime/completed для 1A/07 и start/stop/pause для 18/82.
- Никогда не выводит сырые HCI пакеты, MAC, UID, file ID, nonce, ECDH секрет, binding key или Opus аудио.
- Сообщает факт **наблюдения** опасных команд (0B/87, 0B/8C, 01/B8, 1A/10), но ничего не отправляет на устройство.

Внимание: HCI-захват **не гарантирует получения постоянного 32-байтного binding key**. Он может показать наличие команды 0B/8B, но не позволяет считать её ciphertext безопасным ключом. Нельзя отправлять 0B/8B с угадываемым ключом.

## Что будем искать

Сопоставим порядок команд в официальном приложении с Pocket HUD: 01/01, 2E/01, возможные 01/A6, 0B/8B и другие запросы до успешных 18/82, 1B/0E, 1A/07.

Возможные выводы:

- Официальный Soundcore App тоже получает FF: сначала исследовать состояние устройства, учётной записи и приложения.
- Официальный Soundcore App успешно получает аудио и использует 0B/8B: выяснять безопасный источник **существующего** binding key; не применять bind/unbind/reset.
- Официальный Soundcore App успешно получает аудио без 0B/8B: искать недостающие команды и порядок инициализации или различие транспорта.

Сторонние реализации для сравнения:

- https://github.com/ws/soundcore

## Тесты

Для Python-анализатора есть 5 синтетических модульных тестов: разбиение HCI ACL, протокольный FF, обработка ZIP, ограничения приватности и отклонение повреждённых записей. Подключены к GitHub Actions. **На реальной HCI трассе Motorola тест ещё не проведён**.
