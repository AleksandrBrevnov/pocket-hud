# Очистка хранилища аудиозаписей и ZIP-экспортов (Recording Cleanup)

## 1. Назначение и контекст
PocketHUD сохраняет непрерывные аудиозаписи сессий диалогов (Gemini Live) 10-минутными частями в формате PCM WAV (16 кГц, 16 бит, моно) или AAC M4A в директории `audio_records`. Кроме того, при экспорте разговоров в формате ZIP формируются архивные копии в директории `filesDir/conversation_exports`.

Со временем аудиозаписи и архивные копии начинают занимать значительный объём накопителя устройства. Функционал очистки предоставляет безопасные механизмы контролируемого освобождения места:
1. **Удаление аудио выбранного разговора** после обязательного подтверждения с отображением даты, числа частей и точного объёма в мегабайтах.
2. **Очистка всех готовых ZIP-копий экспорта** отдельной кнопкой в меню записей.

---

## 2. Объём накопителя и оценки размера (Storage Footprint)

Для несжатого PCM WAV (16 кГц, 16 бит mono, 32 000 байт/сек) приблизительный объём аудиоданных составляет:
- **1 минута записи:** ~1.92 МБ (1 920 000 байт в десятичной системе);
- **10 минут записи (1 часть):** ~19.2 МБ (19 200 000 байт);
- **1 час записи (6 частей):** ~115.2 МБ (115 200 000 байт).

### 2.1. Особенности хранения ZIP-экспорта
- Создание ZIP-архива разговора требует дополнительного свободного места на устройстве, сопоставимого с суммарным объёмом упаковываемых файлов.
- Стандартный Android Intent Chooser (`Intent.ACTION_SEND`) не предоставляет обратного подтверждения о том, что выбранное пользователем приложение-получатель завершило копирование или обработку файла архива.
- Поэтому PocketHUD **никогда автоматически не удаляет ZIP-архивы сразу после вызова диалога отправки** — это предотвращает повреждение передачи.
- Экспортные копии архивов накапливаются в директории `conversation_exports` и удаляются пользователем вручную через отдельное действие «Очистить ZIP экспорта».

## 3. Архитектура и безопасность (`RecordingCleanup`)

Вся логика валидации, планирования и удаления вынесена в чистый JVM-хелпер `RecordingCleanup`, изолированный от Android SDK.

### 3.1. Двухфазная модель (Plan & Execute)
1. **Формирование плана (`planConversationAudioCleanup`, `planExportZipCleanup`):**
   - Проверяется легитимность переданного корневого каталога. Если каталог экспорта не существует, возвращается пустой план. Если по пути каталога находится обычный файл — выбрасывается исключение.
   - Вычисляются только те файлы, которые принадлежат выбранной сессии разговора или являются готовыми `.zip`-архивами.
   - В план включаются точный список файлов (`files: List<File>`) и суммарный объём (`totalBytes: Long`).
2. **Выполнение плана (`executePlan`):**
   - Выполняет повторную валидацию безопасности каждого файла непосредственно перед удалением.
   - Фиксирует фактический размер удаляемого файла на момент удаления.
   - Возвращает детализированный результат `CleanupResult`:
     - `deleted`: количество успешно удалённых файлов;
     - `missing`: количество файлов, которые уже отсутствовали на момент удаления (не считается ошибкой);
     - `failed`: количество сбоев удаления;
     - `bytesFreed`: фактически освобождённый объём в байтах;
     - `isSuccess`: `true` только в случае отсутствия сбоев (`failed == 0`).

### 3.2. Инварианты безопасности и изоляция
- **Прямая разрешённая папка:** Файл должен находиться строго на первом уровне разрешённого корневого каталога (`canonicalFile.parentFile == canonicalRoot`).
- **Запрет выхода наружу и symlink:** Следование по символическим ссылкам за пределы корневого каталога строго запрещено. Любые пути `../` или сторонние симлинки приводят к отклонению (`IllegalArgumentException`).
- **Запрет удаления каталогов:** Поддиректории никогда не интерпретируются как аудиозаписи или архивы и не удаляются («directory не file rejected»).
- **Исключение неполных и служебных файлов:** Файлы незавершённой записи (`.part`, `.incomplete`), текстовые конспекты (`.md`) и метаданные (`.json`, `.txt`) строго исключаются из плана удаления аудио.
- **Отсутствие эвристик по подстрокам:** Удаление выполняется только по конкретному списку файлов выбранной сессии, сформированному точной группировкой `sessionId`. Поиск и удаление «похожих файлов» по маске имени запрещены.
- **Поддержка детерминированного тестирования:** Метод `executePlan` принимает интерфейс/лямбду `deleter: (File) -> Boolean`, что позволяет в юнит-тестах детерминированно моделировать частичные сбои файловой системы без моков.

## 4. Пользовательский интерфейс и сценарии работы (`MainActivity`)

### 4.1. Удаление аудиозаписей разговора
1. В диалоге «Записи» пользователь нажимает кнопку **«Разговоры (ZIP)»**.
2. В списке сессий отображаются читаемая дата/время начала разговора и количество готовых частей.
3. При нажатии на разговор открывается контекстное меню:
   - **«Выгрузить ZIP»** — запуск экспорта в архив.
   - **«Удалить аудио разговора»** — переход к подтверждению удаления.
4. **Диалог подтверждения удаления:**
   - Показывает дату разговора, число частей и объём в МБ (в десятичном формате, например `38.4 МБ (38400000 байт)`).
   - Предупреждает о **необратимости**: аудиозаписи будут удалены без возможности восстановления.
   - Поясняет статус конспектов: сохранённые текстовые конспекты останутся, но повторный анализ аудио в Gemini без резервной копии будет невозможен.
   - Содержит кнопки **«Удалить»** и **«Отмена»**. Удаление вызывается **только** при нажатии «Удалить».
5. **Повторный Guard при подтверждении:**
   Перед выполнением повторно проверяется состояние системы:
   - если активна служба `PocketService` (идёт запись или перевод) — операция отклоняется с предупреждением;
   - если выполняется экспорт архива (`conversationExportThread` / прогресс-диалог) — операция отклоняется;
   - если выполняется генерация конспекта по аудио (`AudioSummaryManager.isGenerating`) — операция отклоняется.
6. **Оповещение о результате:**
   - При успешном удалении выводится всплывающее сообщение с количеством удалённых файлов и освобождённым объёмом.
   - При частичном сбое выводится информационный диалог с точным числом удалённых файлов, ошибок и отсутствовавших файлов без сокрытия проблемы.

### 4.2. Очистка готовых архивов экспорта («Очистить ZIP»)
- Кнопка **«Очистить ZIP»** доступна в диалоге «Записи» всегда, в том числе когда список готовых аудиозаписей пуст.
- Диалог очистки поясняет пользователю:
  - найдено количество готовых ZIP-архивов и их суммарный объём;
  - архивы являются копиями для отправки, исходные аудиозаписи и конспекты затронуты не будут.
- По нажатию «Очистить» выполняется валидация состояния сервисов и быстрое последовательное удаление файлов из каталога `conversation_exports`.

### 4.3. Рекомендация по порядку действий
Не рекомендуется предлагать пользователю удалять аудиозаписи разговора до тех пор, пока разговор не был успешно экспортирован во внешний архив или сохранён пользователем. Автоматическая очистка файлов при запуске приложения запрещена.

### 4.4. Доступ к конспектам после удаления аудио
Конспекты без исходного WAV отображаются отдельными пунктами в «Записях» и открываются без повторного запроса к Gemini. Удаление аудио не удаляет эти Markdown-файлы.

### 4.5. Дополнительные проверки мастера
Символьные ссылки исключены из очистки полностью. Исполнитель плана дополнительно защищает конспекты и другие нецелевые расширения. Изменение пути после подтверждения учитывается как ошибка конкретного файла, сохраняя статистику уже удалённых файлов. После успешной очистки список записей обновляется.
