## 3. Review findings / обязательные исправления
- [R1] COMPILE: manager.requestSummary onSuccess принимает SavedAudioSummary, но saveSummary возвращает File и сейчас вызывается onSuccess(saved). Преобразовать сохранённый File через loadSummary либо согласовать возвращаемый тип, сохранить работоспособность тестов. Проверь сигнатуры и Kotlin API всех новых классов, а не объявляй компилируемым без компилятора.
- [R2] TEST FIXTURES: contractWavVerificationAndSampleAccurateSlicing требует пользовательский untracked WAV, которого НЕ будет в CI. НЕ публиковать/не добавлять реальную запись в git. Сделай детерминированный синтетический WAV 70.2s, проверь 640000 PCM байт 20–40s и весь полный диапазон по реальным сэмплам. SHA пользовательского файла остаётся локальной отдельной проверкой, не выдавай синтетику за исходник. В padding test ByteBuffer.allocate(256) меньше header+320bytes; увеличь до точного нужного размера. Удали locateContractWav dependency из обязательного CI.
- [R3] API cleanup warning: return AudioSummaryResult.* вычисляется ДО finally, поэтому присваивание cleanupWarning в finally НИКОГДА не обновляет возвращённый immutable result. Вынеси основную работу во внутренний метод, сохрани result, выполни cleanup затем result.copy(cleanupWarning=...). Обязательно доставить warning и при Success, и при Error, сохранить в sidecar/показать в UI; manager сейчас полностью игнорирует Success.cleanupWarning. Добавь тест DELETE 500 после success и failure.
- [R4] FINISH / HOST / SCHEMA: success разрешать только finishReason == STOP; missing/OTHER/BLOCKLIST/PROHIBITED_CONTENT/unknown не принимать как завершённый текст. API response file name валидировать форматом files/[a-z0-9-]+ по официальному Files schema (поправь mock имена с underscore); fileUri обязателен, не синтезировать по name. Loopback HTTP разрешать только если базовый endpoint самого клиента test loopback и origin совпадает (scheme/host/port); production endpoint не должен принять http://127.0.0.1 и localhost. В проде доверенные HTTPS Google API hosts, redirects off даже при injected client (либо enforce client.newBuilder). Не выводить секретные upload URLs и raw full response в ошибки/логи. В JSON mock request whitelist реально сравнивай наборы keys (root contents; content parts/role при использовании; part fileData или text; fileData mimeType,fileUri). Один `.contains` prompt — не schema validation.
- [R5] CANCEL: cancelCurrent сейчас только увеличивает id, оставляет сетевые операции и Activity closures живыми. Добавить per-request cancellation control с активным okhttp Call.cancel и check перед каждой стадией/поллингом/отправкой inference. Cleanup DELETE должен выполняться отдельным неотменённым запросом. Логическая отмена A не блокирует B за длительным polling A. На finally A не сбрасывает isBusy B. Сам singleton не хранит Context. Удалить фиктивный context parameter getInstance(context) если не нужен. Закрыть executor у тестовых manager instances (например close), иначе тесты оставляют потоки. Избегай catch(Throwable) когда достаточно Exception.
- [R6] COMMIT RACE / ATOMIC SAVE: cancel может сработать после id check, но ДО/ВО ВРЕМЯ saveSummary; сохранение отменённого A произойдёт. Проверить identity на самой границе публикации sidecar под stateLock (подготовку временного файла и hash можно делать до lock), сериализовать commit с cancel. Тест с latch на precommit: A дошёл до commit; cancel A; старт B; отпустить A; только B сохранён и callback B, busy B не сброшен A. Никаких sleep(100)/sleep(200) в роли доказательства stale lifecycle: latch на фактическом запросе/commit, ожидание окончательного completion. 
  Атомарность: fallback сейчас targetFile.delete() и targetFile.writeBytes уничтожают прежний конспект при сбое. Убрать destructive fallback. Если ATOMIC_MOVE unsupported, вернуть понятную ошибку с сохранением старого target (допустимо fail closed), временный файл очистить. Добавить тест инъекцией failed move: старый target byte-for-byte неизменен. Нет слепых ignored exceptions на критичных ветках.
- [R7] EXACT RANGE: filenames/metadata сейчас округляются до .1s, разные выборки 20.01 и20.04 перезапишут друг друга. Используй startFrame/endFrame в sidecar identity; храни точный фактически отправленный диапазон, а не округлённый UI. ISO timestamp с Z сейчас форматирует локальный timezone; используй UTC Instant.now().toString(). Save/load тест сравнивает фактический hash с вычисленным и точные bounds, не просто наличие строк.
- [R8] WHOLE FILE/UI: default end=WavAudioClip.formatSecondsToTime(duration) округляет до десятых. Для 70.2345s будет 70.2 (потеря хвоста); 70.278s округляется за duration и UI вообще не пускает. Нужен явный выбор «Вся запись» (по умолчанию), использующий точную duration/totalFrames, и «Интервал» с полями. В UI/metadata человек видит понятное время, но API передаётся точный конец. Тест whole file 70.2345s проверяет последнюю пару байт и полную длину. formatSecondsToTime не должен выдавать MM:60.0 на округлении.
- [R9] UI LIFECYCLE: runOnUiThread callbacks уже могут стоять в main queue в момент onDestroy, cancelCurrent этого не отменяет. В каждом posted callback проверить !isDestroyed&&!isFinishing и request identity/UI generation. Хранить progressDialog field и dismiss/clear при destroy/cancel. Callbacks из singleton/executor не должны сильно держать Activity: WeakReference/adapter без implicit this capture, либо освобождаемый listener. При onDestroy никакой генерации singleton ради cancel если её вообще не было. Отмена из окна не должна потом показывать error старого запроса.
