# Архитектура и спецификация: Суть по аудиозаписи (TASK-006)

## 1. Обзор функции
Функция «Суть по аудио» в PocketHUD формирует структурированный конспект встречи на русском языке непосредственно из сохранённых аудиозаписей PCM16 mono 16kHz WAV, независимо от запущенного сервиса перевода (`PocketService`) и текстовых реплик диалога.

### Ключевые возможности:
- Выбор готовой аудиозаписи из окна «Записи».
- Выбор режима нарезки: «Вся запись» (по умолчанию, передаётся точная длительность до последнего сэмпла) либо «Интервал» с полями ввода `0 <= start < end <= duration`.
- Точная нарезка PCM фреймов (2 байта на фрейм) во временный WAV без изменения оригинала.
- Прямая отправка аудио в Gemini Files API по протоколу resumable upload (без base64 в памяти).
- Контроль жизненного цикла файла в Gemini: bounded polling до состояния `ACTIVE`, вызов `generateContent` модели `gemini-3.8-flash` (только `finishReason == STOP`), удаление загруженного файла через `DELETE` в блоке `finally`.
- Атомарное сохранение Markdown-конспекта (UTF-8 No-BOM) рядом с исходным аудиофайлом с метаданными (SHA256 оригинала, точные границы startFrame/endFrame, модель, временная метка UTC Instant).
- Автономный просмотр и копирование сохранённых конспектов без обращения к API и без запущенного сервиса.

### 2.1. WavAudioClip (чистый JVM)
- **Валидация:** Проверяет RIFF заголовок, тег `WAVE`, declared `riffSize`, границы всех чанков относительно конца файла и RIFF блока, наличие `fmt ` и `data`.
- **Поддерживаемый формат:** строго `AudioFormat = 1` (PCM), `Channels = 1` (mono), `SampleRate = 16000`, `BitsPerSample = 16`, `ByteRate = 32000`, `BlockAlign = 2`.
- **Устойчивость к повреждениям:** Отклоняет усечённые файлы, пустые `data` чанки, неверные частоты/каналы, non-finite значения времени (NaN, Infinity).
- **RIFF Padding:** Обрабатывает нечётные размеры предшествующих чанков (выравнивание на 2 байта).
- **Фреймовая нарезка:** Вычисляет точные смещения сэмплов:
  $$\text{startFrame} = \text{round}(\text{startSeconds} \times 16000)$$
  $$\text{endFrame} = \text{round}(\text{endSeconds} \times 16000)$$
  При выборе «Вся запись» `endFrame = totalFrames`, что исключает потерю хвоста аудио.
- **Безопасность I/O:** Запрещает совпадение источника и назначения; при обрыве чтения PCM выбрасывает явное исключение `IOException`, исключая тихое усечение.
- **Форматирование времени:** `formatSecondsToTime` округляет десятые доли без артефактов (например, `59.96s` преобразуется в `01:00.0`, а не в невалидное `00:60.0`).

### 2.2. AudioSummaryApi (чистый JVM + OkHttp + org.json)
- **Модель:** исключительно `gemini-3.8-flash`.
- **Авторизация:** заголовок `x-goog-api-key`.
- **Безопасность сетевых вызовов:**
  - Принудительно отключены редиректы (`followRedirects = false`, `followSslRedirects = false`).
  - Upload URL проверяется: loopback HTTP разрешён только при совпадении origin с тестовым loopback base URL; в продакшене разрешены только HTTPS доверенные Google API хосты (`*.googleapis.com`, `*.google.com`).
  - Секретные upload URL и полные тела ответов не выводятся в логи и ошибки.
- **Опрос состояния (Polling):**
  - `PROCESSING` — опрос с интервалом `pollIntervalMs` до `maxPollAttempts`.
  - `ACTIVE` — переход к генерации конспекта.
  - `FAILED`, `STATE_UNSPECIFIED`, неизвестные состояния — ошибка.
  - Дескриптор файла валидируется регулярным выражением `^files/[a-z0-9-]+$`; поле `fileUri` обязательно.
- **generateContent & валидация ответа:**
  - Тело запроса формируется по схеме `contents -> parts -> [fileData, text]`.
  - Принимается только ответ с `finishReason == STOP`. Иные статусы (`MAX_TOKENS`, `SAFETY`, `OTHER`, `BLOCKLIST` и отсутствие поля) возвращаются как ошибка.
  - Части с `thought: true` отбрасываются.
- **Очистка (Cleanup):**
  - Запрос `DELETE /v1beta/files/{name}` выполняется отдельным неотменённым вызовом.
  - Предупреждение об ошибке очистки (`cleanupWarning`) доставляется вызывающей стороне и для успешного конспекта, и для ошибки.

### 2.3. AudioSummaryManager
- **Потокобезопасность и жизненный цикл:** фоновый `ExecutorService`, реализует интерфейс `AutoCloseable` для корректного освобождения ресурсов.
- **Одиночный запрос и отмена:**
  - Защита от параллельных дубликатов (`isBusy`).
  - При отмене (`cancelCurrent()`) инкрементируется идентификатор запроса, и прерывается активный сетевой вызов OkHttp (`Call.cancel()`).
- **Сериализация публикации (Commit):**
  - Подготовка временного файла и расчёт SHA256 выполняются до входа в критическую секцию.
  - Перенос временного файла в целевой выполняется под `stateLock` со строгой проверкой актуальности `reqId`. Отменённый запрос удаляет свой временный файл и не перезаписывает целевой sidecar.
  - Атомарный перенос с безопасным откатом: при неподдерживаемом `ATOMIC_MOVE` выполняется обычный `move`; в случае ошибки операция завершается неудачей без удаления или повреждения ранее существовавшего sidecar-файла (fail-closed).
- **Sidecar-хранилище:**
  - Имя файла формируется с использованием точных номеров фреймов: `<baseName>_f<startFrame>-f<endFrame>.summary.md`. Это предотвращает коллизии при близких дробных долях секунд (например, 20.01с и 20.04с).
  - Frontmatter содержит: `source`, `sha256`, `range`, `startFrame`, `endFrame`, `startSeconds`, `endSeconds`, `model`, `created` (в формате UTC ISO-8601 с суффиксом `Z`), а также `warning` (при наличии).

## 3. Ограничения и особенности

> [!IMPORTANT]
> **Ограничение одной части WAV (10-минутная ротация):**
> Запись Gemini Live в PocketHUD ротируется отдельными WAV-файлами по 10 минут (`record_..._0001.wav`, `record_..._0002.wav`). Функция конспекта строит суть по **одной конкретно выбранной части** (или её интервалу). Сквозное объединение нескольких 10-минутных частей в один общий конспект в текущей версии не выполняется.

> [!NOTE]
> **Файлы каскадного перевода (.m4a):**
> Для записей формата `.m4a` выдаётся явное уведомление: «Суть пока доступна для WAV Live».

## 4. Программа испытаний на реальном устройстве (Device Testing)

Испытания на реальном Android-устройстве проводятся отдельно от JVM unit-тестов.

### 4.1. Предварительные условия:
1. Установлен тестовый APK (версия `1.0.53-audio-summary`, `versionCode 57`).
2. В настройках PocketHUD введён валидный Google AI Studio API-ключ.
3. Проведена тестовая сессия Gemini Live (сохранён хотя бы один `.wav` файл в `audio_records`).

### 4.2. Сценарии ручной проверки:
- [ ] **Сценарий 1: Конспект всей записи (по умолчанию).**
  - Открыть «Записи» -> выбрать `.wav` -> нажать «Суть по аудио».
  - Проверить наличие выбора «Вся запись» по умолчанию.
  - Нажать «Сформировать суть».
  - Дождаться завершения: открывается диалог конспекта с разделами «О чём разговор», «Главное», «Договорённости / действия», «Неясно».
- [ ] **Сценарий 2: Конспект интервала (например, 00:20.0 — 00:40.0).**
  - Переключить на «Интервал», задать границы вручную.
  - Убедиться, что сформирован конспект выбранного отрезка.
- [ ] **Сценарий 3: Автономный просмотр сохранённых конспектов.**
  - Отключить сеть.
  - Открыть «Записи» -> выбрать ту же запись -> «Сохранённые конспекты».
  - Убедиться, что сохранённый конспект открывается моментально без сети.
- [ ] **Сценарий 4: Отмена запроса.**
  - Запустить формирование конспекта и нажать кнопку «Отмена» в диалоге прогресса.
  - Убедиться, что процесс прекращён, UI не завис, повторный запуск работает штатно.
- [ ] **Сценарий 5: Попытка анализа .m4a.**
  - Выбрать файл `.m4a` -> «Суть по аудио».
  - Убедиться в отображении сообщения: «Суть пока доступна для WAV Live».
- [ ] **Сценарий 6: Проверка отсутствия утечек в onDestroy.**
  - Начать генерацию и закрыть Activity.
  - Убедиться в отсутствии сбоев и крэшей приложения.
